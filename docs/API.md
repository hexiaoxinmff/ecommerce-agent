## 0. 基础约定

| 项 | 约定 |
|---|---|
| Base URL | `http://127.0.0.1:8000`（默认） |
| 数据格式 | JSON |
| CORS | 默认仅允许 `http://localhost:5173`（可用环境变量 `CORS_ORIGINS` 覆盖） |
| 认证 | Bearer session：`Authorization: Bearer <access_token>`（注册 / 登录豁免；服务端只存 token 的 SHA-256 哈希，会话 TTL 默认 7 天，可用 `AUTH_SESSION_TTL_SECONDS` 覆盖） |
| 只读 | 所有 SQL 相关接口最终经只读执行器（`mode=ro` + `query_only=ON`） |
| 错误响应 | 统一 `{ "success": false, "error": "<固定文案>" }`（`/api/system/database` 例外，使用 HTTPException） |

通用错误码约定（与 LLM Provider 相关的接口一致）：

| HTTP | 含义 |
|---|---:|
| 422 | 参数校验失败 / SQL 安全拒绝 |
| 500 | 未预期异常（固定文案，不回显 traceback / 路径 / Secret） |
| 502 | LLM Provider 认证失败（401/403）或 LLM/SQL 输出非法 |
| 503 | LLM Provider 未配置 / 限流（429）/ 服务不可用（5xx）/ 超时 / 网络错误；数据库不可用 |

**当前版本未实现的 API（不虚构）**：

- 多轮 conversation API（Multi-turn / 上下文，PRD 阶段 2）。

> 认证（§11：register / login / me / logout）与查询历史（§12）已实现（Task37 起）；`/api/agent/analyze` 需登录后调用（§10）。

## 1. 健康检查

- **方法**：`GET`
- **路径**：`/api/health`
- **用途**：服务与 SQLite 只读连接探活（真实执行 `SELECT 1`）。

> ### ⚠️ 职责边界（第十阶段 §十）
>
> 本接口**只表达三件事**：`Backend 是否在跑`、`Database 是否可读`、`Runtime LLM 配置是什么`。
>
> - 它**不发起任何 LLM 网络请求**，因此**不能**用来判断上游 LLM 是否可用；
> - `llm` 字段是**只读配置展示**（来自 `get_llm_provider()` 的解析结果），
>   前端文案固定为「**已配置**」，**绝不**显示成「可用 / available」；
> - 真实 LLM 可用性只能由 `/api/agent/analyze`（或 `/api/llm/test`）的**实际请求结果**体现。
>
> 实测反例：同一分钟内 `/api/health` 返回 200 且 `llm` 非空，而 `/api/llm/test` 返回 503。
> 这条边界由 `backend/tests/test_health_boundary.py` 守住（含"健康检查不得对外连接"的
> socket 层护栏，以及护栏自身的反向自查）。

Request：无 Body / Query。

Response JSON（200）：

```json
{
  "status": "ok",
  "service": "ecommerce-analysis-agent",
  "database": { "status": "ok", "type": "sqlite", "name": "ecommerce.db" }
}
```

Response JSON（503，数据库不可用）：

```json
{
  "status": "degraded",
  "service": "ecommerce-analysis-agent",
  "database": { "status": "error", "type": "sqlite", "name": "ecommerce.db" }
}
```

错误码：

| HTTP | 场景 |
|---|---:|
| 200 | 服务与数据库均正常 |
| 503 | 数据库不可读（响应体 `status=degraded`，客户端以响应体为准） |

示例：

```bash
curl http://127.0.0.1:8000/api/health
```

## 5. Few-shot 检索

- **方法**：`POST`
- **路径**：`/api/fewshot/retrieve`
- **用途**：规则型本地示例检索（Top-K），不调用 Mimo。返回按 (score 降序, example_id 升序) 排序的参考示例；`score` 是检索相似度，不是 SQL 正确性。

Request JSON：

```json
{
  "question": "2025年每月销售额是多少？",
  "tables": ["orders"],
  "columns": ["orders.order_date"],
  "scenario": null,
  "top_k": 3
}
```

| 字段 | 类型 | 约束 |
|---|---|---|
| question | string | 1~500 字符，不可为空白 |
| tables | string[] | 可选 |
| columns | string[] | 可选；必须使用「表名.字段名」格式，否则 422 |
| scenario | string \| null | 可选 |
| top_k | int | 可选，默认 3，范围 1~50（0 或超大值 → 422） |

Response JSON（200）：

```json
{
  "success": true,
  "result": {
    "examples": [
      {
        "example_id": "…",
        "question": "…",
        "sql": "…",
        "score": 0.87,
        "matched_reasons": ["…"]
      }
    ]
  }
}
```

错误码：

| HTTP | 场景 |
|---|---|
| 200 | 正常 |
| 422 | question 空 / top_k 越界 / columns 格式非法 |
| 500 | 数据集加载失败（文件缺失 / JSON 非法 / 表字段不存在等）或未预期异常 |

示例：

```bash
curl -X POST http://127.0.0.1:8000/api/fewshot/retrieve \
  -H "Content-Type: application/json" \
  -d '{"question": "2025年每月销售额是多少？", "top_k": 2}'
```

## 7. SQL 执行

- **方法**：`POST`
- **路径**：`/api/sql/execute`
- **用途**：只读执行 SELECT / WITH（含 UNION）。只接收 SQL，不接收自然语言；执行前再次做 SQL Safety Validation。结果超限不崩溃：返回 200 + `truncated=true`。

Request JSON：

```json
{ "sql": "SELECT region, COUNT(*) AS user_count FROM users GROUP BY region ORDER BY user_count DESC LIMIT 1" }
```

| 字段 | 类型 | 约束 |
|---|---|---|
| sql | string | 1~10000 字符，不可为空白；单条只读语句 |

Response JSON（200）：

```json
{
  "success": true,
  "result": {
    "columns": ["region", "user_count"],
    "rows": [["广东", 246]],
    "row_count": 1,
    "truncated": false,
    "execution_time_ms": 3.214
  }
}
```

错误码：

| HTTP | 场景 |
|---|---|
| 200 | 执行成功（含 `truncated=true` 的截断场景） |
| 422 | sql 空 / 空白 / 超长；安全校验失败（写操作 / 多语句 / 无法解析等） |
| 500 | 数据库执行异常（语法错误 / 表不存在等）；未预期异常 |

示例：

```bash
curl -X POST http://127.0.0.1:8000/api/sql/execute \
  -H "Content-Type: application/json" \
  -d '{"sql": "SELECT COUNT(*) AS n FROM orders"}'
```

## 9. SQL 执行（有限 Repair 闭环）

- **方法**：`POST`
- **路径**：`/api/sql/execute-with-repair`
- **用途**：Safety → Execute → 失败 → Repair(一次) → Safety/Schema → Execute(一次)。**最多 1 次 Repair / 2 次执行，绝不循环。**

Request JSON：

```json
{
  "question": "2025年每月销售额是多少？",
  "sql": "SELECT strftime('%Y-%m', order_date) AS ym, SUM(total_amount) AS total FROM orders GROUP BY ym",
  "tables": ["orders"],
  "columns": ["orders.order_date"]
}
```

| 字段 | 类型 | 约束 |
|---|---|---|
| question | string | 1~500，不可为空白 |
| sql | string | 1~10000，不可为空白 |
| tables / columns | string[] | 可选 |

Response JSON（200，直接成功）：

```json
{
  "success": true,
  "result": {
    "question": "…",
    "sql": "…",
    "execute_count": 1,
    "repair_count": 0,
    "original_error": "",
    "repaired_sql": "",
    "repair_reason": "",
    "repair_error": "",
    "result": { "columns": ["…"], "rows": [], "row_count": 0, "truncated": false, "execution_time_ms": 3.5 }
  }
}
```

Response JSON（422，闭环最终失败）：`success=false` + `result`（含 `original_error` / `repair_error` 等完整诊断）+ `error`。

错误码：

| HTTP | 场景 |
|---|---|
| 200 | 闭环成功（含 Repair 后成功） |
| 422 | 参数非法；Repair 后仍失败（success=false + 完整诊断） |
| 500 | 未预期异常（固定文案） |

> 注意：本接口对 LLM Provider 错误不单独映射 HTTP 状态（作为闭环内部步骤处理），失败统一以 422 + 诊断返回。

## 10. Agent 编排分析（核心入口）

- **方法**：`POST`
- **路径**：`/api/agent/analyze`
- **用途**：Question → SchemaLinking → Few-shot → SQL 生成 → Safety → Execute →（Repair ≤1）→ 二次执行 → Result + Trace。有界：`repair_count ≤ 1`、`execute_count ≤ 2`。
- **认证**：必需，`Authorization: Bearer <access_token>`（未登录 / token 无效或过期 → 401）。每次请求（成功或失败）都会按当前登录用户写入一条查询历史。

Request JSON：

```json
{ "question": "2025年每月销售额是多少？" }
```

| 字段 | 类型 | 约束 |
|---|---|---|
| question | string | 1~500 字符，不可为空白 |

Response JSON（200）：

```json
{
  "success": true,
  "result": {
    "question": "2025年每月销售额是多少？",
    "success": true,
    "generated_sql": "…",
    "repaired_sql": "",
    "execution_result": {
      "columns": ["ym", "total_sales"],
      "rows": [["2025-01", 725433.47]],
      "row_count": 12,
      "truncated": false,
      "execution_time_ms": 5.5
    },
    "execution_error": "",
    "repair_reason": "",
    "repair_error": "",
    "execute_count": 1,
    "repair_count": 0,
    "final_error": "",
    "trace": [
      {
        "sequence": 1,
        "node": "schema_link",
        "status": "success",
        "duration_ms": 3200.5,
        "message": "",
        "input_summary": {},
        "output_summary": {}
      }
    ],
    "total_time_ms": 12500.4,
    "http_status": null,
    "error_type": ""
  },
  "error": ""
}
```

错误码：

| HTTP | 场景 |
|---|---|
| 200 | 分析成功（含 200 级业务失败，见 `result.success` / `final_error`） |
| 401 | 未登录 / token 无效或过期（统一文案 `Invalid credentials`） |
| 422 | question 参数非法 |
| 502 | LLM Provider 认证失败（401/403） |
| 503 | Mimo 未配置 / 限流 / 服务不可用 / 超时 / 网络错误 |
| 500 | 未预期异常（固定文案 `Agent analysis internal error`） |

Trace 节点序列：`schema_link` → `fewshot_retrieve` → `sql_generate` → `sql_safety` → `sql_execute` →（可选）`sql_repair` → `sql_execute_repaired`；每个 TraceEvent 含 `status ∈ {success, error, skipped}`。

示例：

```bash
curl -X POST http://127.0.0.1:8000/api/agent/analyze \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <access_token>" \
  -d '{"question": "2025年每月销售额是多少？"}'
```

## 11. 认证（Auth）

安全基线（与实现一致）：口令使用 PBKDF2-HMAC-SHA256（600,000 次迭代 + 随机盐）哈希存储；会话 token 由服务端生成（256 bit 熵），数据库只存其 SHA-256 哈希；任何响应均不包含 `password_hash` / `token_hash`。认证失败统一返回 401 `{"detail": "Invalid credentials"}`，抑制用户枚举。

### 11.1 注册

- **方法**：`POST`
- **路径**：`/api/auth/register`
- **认证**：无（豁免）。

Request JSON：

```json
{ "username": "alice", "email": "alice@example.com", "password": "S3cret!pass" }
```

| 字段 | 类型 | 约束 |
|---|---|---|
| username | string | 1~64 字符，trim 后非空；全局唯一 |
| email | string | 3~254 字符，trim + 转小写，基础格式校验；全局唯一 |
| password | string | 1~1024 字符，非空 / 非纯空白（不 trim，保留内部空格） |

Response JSON（201）：

```json
{ "id": 1, "username": "alice", "email": "alice@example.com", "is_active": true }
```

错误码：

| HTTP | 场景 |
|---|---|
| 201 | 注册成功 |
| 409 | username 或 email 已被注册（`detail` 区分两种文案） |
| 422 | 字段校验失败 |

### 11.2 登录

- **方法**：`POST`
- **路径**：`/api/auth/login`
- **认证**：无（豁免）。

Request JSON：

```json
{ "username": "alice", "password": "S3cret!pass" }
```

Response JSON（200）：

```json
{
  "access_token": "<原始 token，仅此一次返回>",
  "token_type": "bearer",
  "expires_at": "2026-10-02T12:00:00+00:00",
  "user": { "id": 1, "username": "alice", "email": "alice@example.com" }
}
```

错误码：

| HTTP | 场景 |
|---|---|
| 200 | 登录成功（签发会话） |
| 401 | 用户不存在 / 已停用（is_active=false）/ 密码错误（统一文案） |

### 11.3 当前用户

- **方法**：`GET`
- **路径**：`/api/auth/me`
- **认证**：必需（Bearer）。

Response JSON（200）：

```json
{ "id": 1, "username": "alice", "email": "alice@example.com", "is_active": true }
```

错误码：401（header 缺失 / 非 Bearer / token 无效或会话过期）。

### 11.4 登出

- **方法**：`POST`
- **路径**：`/api/auth/logout`
- **认证**：必需（Bearer）。
- **语义**：删除当前 token 对应的服务端会话（用户其他端会话不受影响）；该会话产生的查询历史全部保留，仅解除 `session_id` 关联。

Response：204 No Content（无 body）。

错误码：401（未登录 / token 无效）。

## 12. 查询历史（History）

历史由 `/api/agent/analyze` 在每次请求后自动写入（成功与失败都写，`success` 字段区分），**按服务端登录态的 user_id 强制隔离**；本组接口只能读 / 删本人的历史。响应不含 `user_id` / `session_id` / 任何哈希字段。

### 12.1 历史列表

- **方法**：`GET`
- **路径**：`/api/history`
- **认证**：必需（Bearer）。

Query 参数：

| 参数 | 类型 | 约束 |
|---|---|---|
| page | int | ≥1，默认 1 |
| page_size | int | 1~100，默认 20 |

Response JSON（200）：

```json
{
  "items": [
    {
      "id": 42,
      "question": "2025年每月销售额是多少？",
      "sql": "SELECT …",
      "success": true,
      "error_message": "",
      "result_summary": "12 行 · 列: ym, total_sales",
      "row_count": 12,
      "total_time_ms": 12500.4,
      "created_at": "2026-09-25T12:00:00+00:00"
    }
  ],
  "page": 1,
  "page_size": 20,
  "total": 1
}
```

`items` 按 `created_at` 倒序（同秒按 id 倒序）。

> **消费方（第九阶段 Phase F）**：首页「最近动态」调用本接口（`page_size=5`），
> 点击一条记录会把该条 `question` **回填到首页提问框**，但**不自动发起查询**
> （自动执行会产生一次真实 LLM 调用，不该由一次误点触发）。
> 完整列表（含分页与删除）在「历史记录」页。
>
> ⚠️ **时间显示口径**：`created_at` 是 **UTC 带显式偏移** 的字符串
> （由 `appdb.now_iso()` 写入）。前端**必须**经
> `frontend/src/utils/datetime.ts` 转用户本地时区后再渲染。
> 历史上 `HistoryPage` 用 `iso.replace("T"," ").slice(0,19)` 直接截断，
> 等于把 **UTC 墙上时钟当成用户本地时间** 展示（北京用户会看到早 8 小时、
> 且页面上没有任何时区标记的时间）—— 数字是真的、语义是错的，属失真展示，
> 已于第九阶段 Phase F 修复；首页「最近动态」的相对时间共用同一模块。

错误码：401（未登录）；422（分页参数越界）。

### 12.2 删除一条历史

- **方法**：`DELETE`
- **路径**：`/api/history/{history_id}`
- **认证**：必需（Bearer）。
- **语义**：仅能删除本人的历史；不存在或不属于本人一律 404（统一文案 `History not found`，不泄露归属）。

Response：204 No Content（无 body）。

错误码：401（未登录）；404（不存在或非本人）。

## 13. 首页业务概览（Insights）

### 13.1 业务概览聚合

- **方法**：`GET`
- **路径**：`/api/insights/overview`
- **认证**：**必需（Bearer）**。无 header / 非 Bearer / 未知 token / 过期会话一律 401
  `{"detail": "Invalid credentials"}`（带 `WWW-Authenticate: Bearer`）。
- **语义**：首页 Dashboard 的**唯一**业务数据来源。后端在**单条只读连接**
  （`mode=ro` + `PRAGMA query_only=ON`）上执行**模块内固定 SQL**：
  不接收任何参数、不调用 LLM、不写任何数据库/文件/缓存。

> ⚠️ **边界**：这是「访问门禁」，不是「数据隔离」。聚合口径是**全库**的，
> 刻意**不**按 `user_id` 过滤；响应体不含任何用户身份字段。
> 若将来需要按用户隔离的业务数据，**必须另开接口**，不得改这里的口径。
> 前端配套：`HomePage` 已纳入 `ProtectedRoute`，未登录直接渲染登录页。

响应字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `as_of` | `string \| null` | 数据截止日 = `MAX(orders.order_date)`。**前端必须展示**，否则「本月」会被误读为完整自然月 |
| `generated_at` | `string` | 响应生成时刻（UTC ISO 8601） |
| `kpis` | `object` | 4 张 KPI 卡：`month_sales` / `month_orders` / `users_total` / `avg_order_value` |
| `sales_trend` | `array` | 近 12 个月销售额，`{month, sales}` 正序（`sales` 单位：元） |
| `category_distribution` | `array` | 叶子类目 Top 5，`{category, sales, quantity}` |
| `top_products` | `array` | Top 5 商品，`{rank, product, quantity, sales}` |

`kpis.*` 结构：`{label, value, unit, month}`（`month` 为口径月份，空库时为 `null`）。

**口径**（改动须同步测试与审计报告）：

- 「本月」= `MAX(orders.order_date)` 所在月，**不是** `date('now')`
  （真实库为静态合成数据，最新 `2026-09-12`；用 `now` 会在未来某天算出空月）；
- 销售额一律排除 `status = 'cancelled'`；
- 用户数 = `COUNT(*) FROM users`（全表 2,000；`status='active'` 是 1,707，二者不可混用）；
- 类目分布取**叶子类目**（`parent_id IS NOT NULL`）；
- Top 商品按**销售额**排序（与类目口径统一）。

**刻意不返回**：趋势百分比（无真实来源，不编）、查询历史（用户私有数据，
走 `/api/history` 的既有隔离）、任何用户身份字段。

空数据库：HTTP 200 + 空结构（`as_of=null`、KPI 全 0、三个列表为空），**不是 500**。

错误码：401（未登录 / token 无效）；503（数据库不可用，固定文案
`数据库不可用，请确认 db/ecommerce.db 存在且可读。`，不泄漏路径与 traceback）。

## 14. 错误码汇总

| 状态码 | 通用含义 | 说明 |
|---|---:|---|
| 200 | 成功 | 业务失败以 `success=false` + `error` 表达（部分场景仍 HTTP 200） |
| 201 | 创建成功 | 注册 |
| 204 | 成功无返回体 | 登出 / 删除历史 |
| 401 | 未认证 | 统一文案 `Invalid credentials`（认证接口），抑制用户枚举 |
| 404 | 资源不存在 | 历史 id 不存在或非本人 |
| 409 | 资源冲突 | 注册 username / email 已被注册 |
| 422 | 请求参数非法 / SQL 安全拒绝 | question/sql 空/超长、top_k 越界、columns 格式、写操作/多语句 SQL |
| 500 | 服务内部异常 | 固定文案，不回显 traceback / 路径 / Secret |
| 502 | 上游认证失败 / LLM 输出非法 | Mimo 401/403；非法 JSON / 表字段 / 不安全 SQL / Schema 越界 |
| 503 | 上游不可用 / 未配置 / 数据库不可用 | Key 未配置、429 限流、5xx、超时、网络错误；health 数据库失败 |
