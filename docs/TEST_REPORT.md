### 0.1 Phase G：为什么删掉 `data/demo.ts`，以及怎么证明它没被请回来

`data/demo.ts` 有 15 个导出：**3 个是纯 UI 文案**（`agentStages` / `analysisExamples` /
`exampleQuestions`），**12 个是 0 引用的假业务数据**（`¥7,662,921` / `1,284` / `¥352.6` /
5 个虚构商品名 / `+12.4%` / 一段假 SQL / 一份假 Trace …）。经 import 图审计
（`phaseG_demo_audit.py`）确认 12 个导出在 Phase D–F 接真实接口后引用数归零。

删除理由不是「它叫 demo」，而是**留着它是活的隐患**：任何人重新 `import { kpiData }`
就会把 `¥7,662,921` 无声地请回页面，且**没有任何测试会变红**。该文件自己的文件头也写着
「接入真实数据后应删除本文件」，触发条件已满足。3 个 UI 常量迁到 `data/uiCopy.ts`，
让**文件名本身**说明内容性质。

**新增两道会响的守卫**（`frontend/src/data/uiCopy.test.ts`）：

1. **`uiCopy.ts` 不得含业务数值** —— 摊平所有导出后跑 4 条数值形态正则 + 一份
   demo 时代的具体假值清单；
2. **`demo.ts` 不得复活** —— 文件不存在 + `src/` 下零 import 边。

> ⚠️ 写这两道守卫时踩到两个坑，已修并在此记录：
> - **`node:fs` 不可用**：`tsconfig.app.json` 把 `types` 锁成 `["vite/client"]`，
>   这是**有意的边界**（让浏览器代码在类型层面够不到 `process` / `Buffer` / `fs`）。
>   为几条断言方便就把 `"node"` 加进 `types`，等于为写好检查器而拆掉它该守的墙。
>   ⇒ 改用 Vite 原生 `import.meta.glob(…, { query: "?raw" })`，它已被 `vite/client` 覆盖。
> - **自指假阳性**：反向自查的样本若写成完整字面量 `from "./demo"`，而扫描器自身也在
>   `src/` 扫描范围内，那条「无人 import demo」会**把自己判成违规者**（永远修不掉的假红）。
>   ⇒ 样本改为运行期拼装（`from` 与引号拆开），源码文本里不再存在完整 import 形态。

**守卫必须自测**（否则「全绿」可能只是正则写错了）。变异测试三路同时注入 ——
重造 `demo.ts`、新建文件 `import "./demo"`、往 `uiCopy.ts` 注入 `¥7,662,921` ——
结果 **8/10 变红**，且两条反向自查**保持绿**（它们测的是正则，不是仓库状态）。
还原后 sha256 与变异前逐字节一致（`208a0520…`）。

**独立于单元测试的捆绑证据**（`bundle_sentinel_scan.py`）：源码干净 ≠ 用户下载到的 JS 干净，
所以直接数产物字节。Phase G 前（陈旧产物 `index-1yM7_xld.js`，sha256 `3BC5A022…`）
假值指纹 **17 处**；重建后（`index-BzKNy1QL.js`，sha256 `E262857A…`）**0 处**。
控制组同表给出，用于排除「扫描器读错文件」：`className` 412→437（两份都能数到）、
`页面不会回退到任何静态演示数据` 0→1（诚实文案没被误删）、
`api/insights/overview` 0→4（新包确实含真实接口代码路径）。

> ⚠️ 扫描串必须用**完整短语**：裸名词「静态演示数据」会命中错误态那句**必须存在**的诚实文案
> 「页面不会回退到任何静态演示数据。」，把它误报成泄漏 —— 又一个「扫描串太粗 ⇒ 假阳性」。

> ⚠️ **本节最该记住的不是 25 个 PASS，而是检查器自己坏了三次。**
> 前两次的失败表现**完全指向被测系统**，若不做旁证就会得出「Phase I 被阻塞」的错误结论。
>
> 1. **选择器歧义**：`Hero.tsx:43` 与 `AnalysisPage.tsx:250` **共用同一个
>    `aria-label="输入自然语言查询问题"`** ⇒ 「输入框就绪」在**首页**上也成立。
>    ⇒ 改为侧边栏内点击 + `nav-item--active` 自证 + 等待 `.analysis-input` 出现且 `.hero` 消失。
>
> 2. **登录等待条件恒真**：旧写法等 `aside.sidebar !== null`，但 `AppShell` **永远**返回
>    `<MainLayout>`，而 `MainLayout` 无条件渲染 `<Sidebar />` —— 连未登录时的 `LoginPage`
>    也带着侧边栏，该条件**恒为真**。实测时间线（`dom_nav_diag.mjs`，**0 LLM 成本**）：
>    ```
>    t= 785ms nav="智能分析" hero=false inputs=2 bodyLen=171  ← 其实是登录页
>    t=1202ms nav="首页"     hero=true  inputs=1 bodyLen=663  ← 登录返回后被弹回首页
>    ```
>    根因：`LoginPage.handleSubmit` 在 `await login()` 后调用 `onSuccess?.()`
>    （`LoginPage.tsx:43-47`），而当时挂载的是**首页那条** `ProtectedRoute` 传入的
>    `onSuccess = () => setPage("home")`，把刚点出的「智能分析」覆盖回「首页」。
>    ⇒ 修法：登录等待改为**只有已认证才成立**的条件（`input[type=password]` 消失 **且** `.hero` 出现）。
>
> 3. **轮询参数错位 ⇒ 轮询体执行 0 次**：`waitFor` 签名是 `(predicate, tries, gap)`，
>    但两个调用点仍按旧签名多传了 `label`，使 `tries` 收到字符串 `"real result"`，
>    `for (let i = 0; i < "real result"; i += 1)` 的 `0 < NaN` 恒为 false ⇒
>    **一次都不轮询，立刻返回 `false`**。表现是「真实结果上屏 / 历史记录」双双 FAIL，
>    看起来像后端坏了。这是铁律 14「检查器崩溃会被读成全绿」的**镜像版本**：
>    检查器**静默失效**会被读成「被测对象全红」。
>    ⇒ 修法：`waitFor` 参数改为**显式断言**，非法即抛，不再静默返回 `false`。
>
> **定位方法论（值得复用）**：先跑 **0 LLM 成本**的导航诊断证明「登录→切页」链路本身没问题
> → 再用 CDP `Network` 域证明浏览器发出的 `POST /api/agent/analyze` **8.9 s 拿到 200**
> → 同时用 Python 直连证明后端 5.8 s 返回 200 且 `app.db` **无新增行**
> ⇒ 三个旁证收敛到「检查器自己坏了」。
> **「三个旁证指向同一结论」比「把主脚本改到绿」可靠得多。**

网络层旁证（`dom_net_diag.mjs`，CDP `Network` 域）：`remote=127.0.0.1:8001`、
`proto=http/1.1`、`requestWillBeSentExtraInfo` 里**无任何 `Proxy-*` / `Via` / `X-Forwarded-*`**
⇒ 浏览器直连本地后端，未被代理接管。加载初期若干 `net::ERR_ABORTED canceled=true`
是 **React StrictMode 开发态双挂载**的正常现象（effect 挂载→清理→再挂载，首次请求被主动取消）。
