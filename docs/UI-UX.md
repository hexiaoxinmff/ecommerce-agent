## 2. 设计原则

### 2.1 数据优先（第一原则）

用户第一眼应该看到：**我的问题 / 我的数据 / 我的结论**。页面视觉重心始终落在数据与分析结果上，装饰不得抢占比数据更重要层级。

### 2.2 AI 感克制

AI 是能力，不是视觉主角。AI 元素只体现智能能力（自然语言输入、链路可解释、执行状态），**禁止做成聊天机器人页面**（大量气泡、拟人化动画、满屏对话流）。

### 2.3 高级感

高级感通过以下手段实现，而不是堆特效：

- **空间**：充足留白，内容不拥挤；
- **层次**：清晰的背景 → 卡片 → 内容 → 强调 四级层次；
- **光影**：克制的渐变与光晕，只出现在关键区域；
- **排版**：统一的字体、字号、行高、对齐；
- **色彩**：深海军蓝为主基调，蓝紫为辅助，低饱和度大面积 + 高饱和点缀。

### 2.4 可读性优先（投影硬约束）

尤其考虑课堂投影：核心数字、标题、用户问题、执行状态、图表标签**不能过小**；关键信息禁止用细灰字、低对比边框、淡色文字表达。远距离（约 5～8 米）必须可读。

### 2.5 可追踪

用户能够看到完整链路：

```text
问题 → Schema → SQL → 执行 → 结果
```

视觉层级为：**结果优先，SQL 次之，调试信息进一步下沉**（默认折叠，可展开查看）。

## 4. 字体系统

### 4.1 字体栈

| 类型 | 优先级 |
|---|---|
| 中文 | `"PingFang SC"` → `"HarmonyOS Sans SC"` → `"Source Han Sans SC"` → `"Microsoft YaHei"` → `sans-serif` |
| 英文 / 数字 | `"Inter"` → `"SF Pro Display"` → `"Segoe UI"` → `sans-serif` |
| SQL / 代码 | `"JetBrains Mono"` → `"Cascadia Code"` → `"Consolas"` → `monospace` |

### 4.2 字号规范（投影可读性优先）

| 层级 | 字号 | 字重 | 行高 | 说明 |
|---|---|---|---:|---:|---|
| 页面标题 | 30px（汇报模式 32px） | 700 | 1.3 | 页面顶部大标题 |
| 一级标题 | 24px | 600 | 1.3 | 区块标题、Hero 欢迎语 |
| 二级标题 | 18px | 600 | 1.4 | 卡片标题 |
| 正文 | **16px**（最小 15px） | 400 | 1.6 | 正文、表格内容、问题文案 |
| 辅助文字 | 13px | 400 | 1.5 | 时间、元信息、说明（**禁止用于关键信息**） |
| KPI 数字 | **44px**（首页）/ 36px（结果页） | 700 | 1.1 | 大数字，远距离可读 |
| SQL 代码 | 15px | 400 | 1.6 | 高可读代码，区域高度 ≥ 220px |

### 4.3 硬性要求

- **不使用细字体（font-weight < 400）表达任何正文或关键信息**；
- 核心 KPI、查询问题、结果数值、图表标签必须满足投影可读（正文 ≥ 15px，KPI ≥ 36px）；
- 数字使用 `font-variant-numeric: tabular-nums`（等宽数字），保证表格/ KPI 对齐稳定。

## 5. 间距系统

统一 Spacing Token，禁止页面随意设置间距：

```text
space-4   = 4px    （图标与文字间隙）
space-8   = 8px    （紧凑间距、标签内距）
space-12  = 12px   （列表项内距、输入框内距）
space-16  = 16px   （卡片内距、表单间距）
space-20  = 20px   （区块内距）
space-24  = 24px   （页面内边距、卡片间距）
space-32  = 32px   （大区块间距）
space-40  = 40px   （页面级分区间距）
space-48  = 48px   （Hero 与下方内容间距）
```

规则：

- 卡片内距：统一 `16px`（紧凑）或 `20px`（常规），同一页面必须一致；
- 卡片之间：`16px`（网格内）/ `24px`（区块级）；
- 页面内容区与左右边缘：`24px`；
- 分组标题与内容间距：`12px`。

## 6. 圆角 / 阴影 / 边框 / 光效

### 6.1 Border Radius

| Token | 值 | 适用 |
|---|---|---|
| `radius.sm` | 6px | 小组件：输入框、按钮、标签、Badge |
| `radius.md` | 10px | 卡片 |
| `radius.lg` | 14px | 大容器：Hero、模态框、汇报模式主区域 |
| `radius.full` | 999px | 胶囊按钮、状态圆点 |

### 6.2 Border

- 默认边框：`border.default`（透明度 0.14，极轻描边，用于卡片与分隔）；
- 强调边框：`border.strong`（透明度 0.30，输入框聚焦、选中卡片）；
- 关键状态（成功/失败/拦截）使用**色块 + 文字**表达，不依赖细边框。

### 6.3 Shadow

深色主题下**禁止夸张黑影**，使用低透明度深蓝黑色，模拟「光从上方来」：

| Token | 值 |
|---|---|
| `shadow.card` | `0 2px 8px rgba(3, 8, 20, 0.35)` |
| `shadow.pop` | `0 6px 20px rgba(3, 8, 20, 0.50)` |

### 6.4 Glow

**只允许在以下 4 类位置使用**（其余位置一律禁止）：

1. AI 核心区域（AI 标识、Agent 流程进行中的节点）；
2. 主按钮；
3. 当前选中状态（导航选中项）；
4. 重点交互（「开始分析」按钮）。

Glow 值统一为 `0 0 12px rgba(61, 139, 255, 0.35)`（AI 场景用 `rgba(139, 124, 246, 0.40)`）。

**禁止整个页面到处发光、霓虹弥漫。**

## 10. 数据分析页

**重点页面。** 必须体现完整链路：

```text
用户问题 ↓ Agent 分析过程 ↓ SQL ↓ 执行结果 ↓ 图表/结果
```

### 10.1 问题卡片

顶部卡片：显示用户原始问题（正文 16px+，`text.primary`），左侧问题图标；下方附「提问时间」。

### 10.2 Agent 流程（链路条）

水平步骤条，展示 **7 个阶段**（与最小 Text2SQL 基线链一一对应），每阶段含状态：

```text
问题理解 ✓ → Schema 匹配 ✓ → Few-shot ✓ → SQL 生成 ✓ → SQL 校验 ✓ → SQL 执行 ✓ → 结果生成 ✓
```

对应正式冻结的最小基线链：

```text
Question
→ Schema Linking
→ Few-shot Retrieval
→ SQL Generation
→ SQL Validation
→ SQL Execution
→ Structured Result
```

> 最后一阶段 **Structured Result / 结果生成** 必须存在，不得遗漏。

- 进行中：该节点主色高亮 + 轻量进度动画 + 「正在…」文案；
- 完成：绿色 ✓；
- 失败/拦截：红色 ✗ + 阶段名称高亮；
- 点击阶段可展开该阶段 Trace 摘要（P1 完整 Trace）。

### 10.3 KPI 结果

查询结果若为聚合数字，以大数字卡片呈现（36px+，同首页 KPI 规范）。

### 10.4 Result Table

高可读性表格（规范见第 17.2 节）。列名 = 结果表头，数据 = 查询行；数字右对齐，空值显示 `—`。

### 10.5 SQL（默认折叠）

「查看 SQL」展开入口：点击后展开代码区域（代码字体 15px，区域 ≥ 220px，带复制按钮）。**默认不堆在首屏。**

### 10.6 执行状态

## 15. 状态设计

每个状态必须同时定义：**视觉 / 文案 / 用户下一步**。

| 状态 | 视觉 | 文案（示例） | 用户下一步 |
|---|---|---|---|
| Loading | 主色旋转图标 + 环节文案，位于链路条当前节点；禁用提交按钮 | 「正在理解问题…」「正在生成 SQL…」 | 等待；可点击「取消」 |
| Success | 绿色 ✓ + 结果内容 + 耗时 | 「SQL 校验通过 · 执行成功 · 耗时 2.3s」 | 查看结果 / 查看 SQL / 继续提问 |
| Warning | 橙色 ⚠ + 结果（部分成功） | 「查询成功，但结果可能不完整」 | 检查提示后确认结果 |
| Error | 红色 ✗ + 友好错误卡 | 「查询执行失败，请稍后重试或调整问题」 | 重试 / 换一种问法 |
| Empty | 居中占位图标 + 引导文案 | 「还没有分析记录，输入问题开始吧」 | 输入第一个问题 |
| Blocked / Security Reject | 红 Badge + 拦截卡（安全盾图标） | 「该查询超出允许范围，已被安全系统拦截」 | 调整问题 / 查看拦截原因（Trace） |
| No Data | 灰蓝占位 + 文案 | 「查询成功，但没有匹配的数据」 | 调整时间范围或条件 |
| Unsupported Question | 灰蓝占位 + 建议 | 「无法从当前数据回答该问题，建议改为……」 | 参考示例问题 / 换一种问法 |

> 错误内部细节（表名、堆栈、Schema 详情）只进 Trace / 日志，**不进用户响应**（与 PRD 第 14 节安全要求一致）。

## 16. 图表设计规范（ECharts）

### 16.1 推荐 / 禁止

| 推荐 | 禁止 |
|---|---|
| 折线图（趋势） | 3D 图 |
| 柱状图（分类/对比） | 过度动画 |
| 饼图 / 环形图（占比，≤ 6 片） | 颜色过多（> 6 色） |
| Top-N 条形图 | 复杂渐变 |
| | 难以阅读的标签 |

### 16.2 组件规范

| 组件 | 规范 |
|---|---|
| 标题 | 16px，`text.primary`，左对齐 |
| 图例 | 13px，`text.secondary`，顶部右侧 |
| 坐标轴 | 轴线 `border.default`；轴标签 13px `text.secondary`；刻度清晰 |
| Tooltip | 深色背景 `#0B1220` + `border.strong`，文字 14px |
| 数据标签 | 关键数据点显示，14px `text.primary`，禁止标签互相遮挡 |
| 主色/辅助色 | 数据色板第 1、2 色为主，辅助色克制使用 |

### 16.3 硬性要求

- **投影后仍能看清趋势**：线宽 ≥ 2px，柱宽 ≥ 12px，标签 ≥ 13px；
- 网格线：极淡 `border.default`，不干扰数据；
- 不启用过度动画（入场 300ms 淡入即可）。

## 18. 动效

动效**必须克制**，总原则：动效服务于理解，不服务于炫技。

### 18.1 允许

- 页面淡入（300ms，不位移或轻微位移）；
- 状态变化（Badge/步骤节点颜色过渡 150ms）；
- 进度动画（Agent 流程「进行中」节点轻量闪烁/进度条）；
- 主按钮交互（Hover 提亮 + Active 按压缩放，120ms）；
- AI 分析状态动画（链路节点推进，克制，无粒子）。

### 18.2 禁止

- 大量粒子、星云、浮动光斑；
- 复杂背景动画、全屏动效；
- 长时间 loading 动画（超过 3s 必须给出环节文案，而非无限旋转）；
- 任何影响信息阅读的动态效果（跳动数字、弹窗抖动等）。
