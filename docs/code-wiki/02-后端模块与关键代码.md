## 2. `db/` — 数据库访问层

### 2.1 `db/sqlite.py` — 业务库（**只读**）

| 名称 | 说明 |
|---|---|
| `TABLE_NAMES: Final[tuple]` | 5 张业务表：`users` / `categories` / `products` / `orders` / `order_items` |
| `_readonly_uri(path)` | 构造跨平台 URI：`file:<abs>?mode=ro`（对空格/百分号做编码） |
| `get_connection() -> sqlite3.Connection` | **双重只读**：URI `mode=ro` + `PRAGMA query_only=ON`；`row_factory=Row`；调用方负责 `close()` |
| `is_database_readable() -> bool` | 轻量探活（`SELECT 1`） |
| `get_database_info() -> dict` | 数据库名 + 表数 + 5 表行数（全部真实查询） |
| 异常 | `DatabaseError` / `DatabaseNotFoundError` / `DatabaseConnectionError` |

> 本层**不提供任何写方法**。写入会被 SQLite 以 `OperationalError` 拒绝。

### 2.2 `db/appdb.py` — 应用库（**可写**，认证/会话/历史）

**三张表**（DDL 常量 `APP_SCHEMA_DDL`）：`auth_user` / `auth_session` / `query_history`（含 3 个索引）。

| 函数 | 作用 |
|---|---|
| `now_iso() -> str` | 当前时刻 ISO 8601 UTC（秒级） |
| `get_connection()` | 可写连接（`PRAGMA foreign_keys=ON`） |
| `init_app_db() -> Path` | **幂等**建库建表（`scripts/init_auth_db.py` 调用） |
| `create_user(username, email, password_hash) -> int` | 建账号；冲突抛 `IntegrityError`（**只收哈希，不收明文**） |
| `get_user_by_username` / `get_user_by_email` / `get_user_by_id` | 参数化查询 |
| `create_session(user_id, token_hash, expires_at) -> int` | 写会话（**只存 token 哈希**） |
| `get_session(token_hash)` / `delete_session(token_hash) -> bool` | 会话查询/删除 |
| `create_query_history(user_id, question, *, session_id, sql, success, error_message, result_summary, row_count, total_time_ms) -> int` | 写历史 |
| `list_query_history(user_id, *, limit=50, offset=0)` | **强制 `user_id = ?`** 隔离 + 分页，按时间倒序 |
| `count_query_history(user_id) -> int` | 分页 total |
| `delete_query_history(user_id, history_id) -> bool` | 跨用户删除返回 `False` |

**关键实现细节**：`delete_session()` 删除会话前，先把该会话在 `query_history.session_id` 上的引用置 `NULL`（历史记录全部保留），否则外键约束会导致「有查询历史的用户登出失败」（Task38 G7）。任一步失败整体回滚。

## 3. `llm/` — LLM Provider 抽象

### 3.1 `llm/provider.py` — 抽象与工厂（**全层唯一分派入口**）

| 名称 | 说明 |
|---|---|
| `LLMProvider(Protocol)` | 成员：`name` / `model` / `generate(messages, *, temperature=0.0) -> str` |
| `LLMError(Exception)` | 基类，携带 `http_status` 与 `provider_error_code`（上游结构化错误码，默认 `None`） |
| 异常族 | `LLMProviderNotConfiguredError` / `LLMApiKeyNotConfiguredError` / `LLMAuthenticationError` / `LLMQuotaError` / `LLMInsufficientBalanceError` / `LLMRateLimitError` / `LLMServiceUnavailableError` / `LLMTimeoutError` / `LLMNetworkError` |
| `provider_error_code_of(exc) -> str \| None` | 安全读取结构化错误码；`None` 表示「不可判定」，调用方须走保守分支 |
| `get_llm_provider() -> LLMProvider` | 按 `LLM_PROVIDER` 返回实例（见下） |

**`get_llm_provider()` 分派逻辑**：
```text
mimo    → MimoProvider()
bailian → BailianModelPool.from_env()
            ├─ fallback_router_enabled → FreeTierFallbackRouter(pool, build_bailian_provider)
            ├─ 有 fallbacks 且锁定    → BailianProvider(model=pool.primary)
            └─ 否则                  → BailianProvider()
其他    → 抛 LLMProviderNotConfiguredError
```
> `LLMQuotaError` 与 `LLMAuthenticationError` **互不继承**：百炼把「免费额度用尽」与「认证失败」都返回 HTTP 403，必须靠 `provider_error_code`（如 `AllocationQuota.FreeTierOnly`）区分。

### 3.2 `llm/mimo.py` — `MimoProvider`

- OpenAI-compatible 实现；**唯一允许 `import openai` 的地方**。
- 客户端**惰性创建 + 实例内复用**（避免每次调用重建，实测 14.9ms / 最坏 403ms）。
- HTTP 状态映射：`401/403 → LLMAuthenticationError`、`402 → LLMInsufficientBalanceError`、`429 → LLMRateLimitError`、`>=500 → LLMServiceUnavailableError`，均带 `http_status`。
- SDK 层 `max_retries=0`；**仅对网络类错误**做有限重试（`_NETWORK_RETRY_DELAYS_SECONDS = (2.0, 5.0)`）。
- `mimo-v2.5-pro` 默认开深度思考会强制覆盖 `temperature`，故显式传 `extra_body={"thinking": {"type": "disabled"}}`。

### 3.3 `llm/bailian.py` — `BailianProvider`

- 阿里云百炼（OpenAI-compatible）。**thinking 物理锁死为 `False`**（不依赖配置）。
- 对 HTTP 403 做**细分**：识别 `AllocationQuota.*` → `LLMQuotaError`；`Endpoint.AccessDenied` → 认证类；错误码经正则白名单校验，**绝不承载响应体原文**。

### 3.4 `llm/model_pool.py` — `BailianModelPool`

`BailianModelPool.from_env()` / `validate_model_pool()` / `list_available_models()`；属性 `primary` / `fallbacks` / `fallback_router_enabled`；异常 `ModelPoolConfigError`。

### 3.5 `llm/fallback_router.py` — `FreeTierFallbackRouter`

- 同样满足 `LLMProvider` Protocol（上层调用方式不变）。
- `classify_failure()` 判定某错误是否可切换下一模型；`ModelStateCache` 记录各模型状态；`build_bailian_provider()` 工厂。
- **仅在**「bailian + 显式配置备用池 + 未锁定模型」时启用。

### 3.6 `llm/local_provider.py` — 本地模型 Provider（Task39 实验用）

> 原则：**表名/字段名/类型全部来自真实库**，业务描述保存在代码（`metadata.py`）。

### 4.2 `schema/metadata.py` — `SchemaCatalog`

| `has_table(name)` / `has_column(table, column)` | 合法性复核 |

### 4.3 `schema/validation.py`

`validate_schema_link(tables, columns, confidence, catalog)` —— LLM 输出的 Schema 合法性与「表.字段」格式复核；异常 `SchemaLinkingInvalidError`。

### 4.4 `schema/linker.py` — `SchemaLinker`

| 成员 | 说明 |
|---|---|
| `SYSTEM_PROMPT` | Schema Linking 角色设定 |
| `BUSINESS_RULES` | 业务口径（`subtotal` / `total_amount` / 排除 `cancelled` / ISO 日期） |
| `build_link_prompt(catalog, question) -> str` | 组装用户侧 Prompt |

## 5. `fewshot/` — 规则型示例检索

### 5.1 `fewshot/models.py`
`FewShotExample` / `FewShotQuery`（`question` / `tables` / `columns` / `scenario` / `top_k`）/ `FewShotMatch` / `FewShotResult`。

### 5.2 `fewshot/dataset.py` — 加载与严格校验

| 函数 | 说明 |
|---|---|
| `load_dataset(path=None) -> list[FewShotExample]` | 读 JSON + **逐条严格校验** |
| `get_dataset() -> list` | `@lru_cache(maxsize=1)` 首发缓存 |
| `reload_dataset()` | `cache_clear()` 后重读 |
| 异常 | `FewShotDatasetError` / `FewShotDatasetNotFoundError` / `FewShotDatasetInvalidError` |

**校验规则（禁止静默跳过坏数据）**：缺字段 / 重复 `example_id` / SQL 为空 / 表不存在 / 字段格式非「表.字段」/ 字段归属表不在 `tables` → 一律报错。

### 5.3 `fewshot/retriever.py` — `FewShotRetriever`

**打分公式**（可解释、确定性、**无向量库、无 LLM**）：
```text
score = 0.30*keyword + 0.25*table_overlap + 0.25*column_overlap + 0.20*scenario
```
| 分量 | 计算 |
|---|---|
| `keyword` | 问题 vs（示例问题+tags）的中文关键词集合 Jaccard |
| `table_overlap` | 用户 tables vs 示例 tables 的 Jaccard |
| `column_overlap` | 用户 columns vs 示例 columns 的 Jaccard |
| `scenario` | scenario 完全相等=1.0；否则 `0.5 * tags Jaccard` |

- `KEYWORDS`：中文关键词词表（销售额/销量/近30天/Top…）。
- `retrieve(query) -> FewShotResult`：按 `(score 降序, example_id 升序)` 稳定排序；`top_k<1` 抛 `ValueError`，`top_k>` 数据集按数据集裁剪。
- `score_example(query, example) -> float`：单例打分。
> `score` 是**检索相似度**，不是 SQL 正确性——生成阶段仍需重新生成并验证。

## 6. `sqlgen/` — SQL 生成与安全校验

### 6.1 `sqlgen/safety.py` — AST 级只读校验

| 名称 | 说明 |
|---|---|
| `_WRITE_NODE_TYPES` | `Insert/Update/Delete/Drop/Create/Alter/Replace/Pragma` 黑名单 |
| `_ALLOWED_STATEMENT_TYPES` | `(exp.Select, exp.Union)` 白名单 |
| `_parse_single_readonly(sql)` | 内部共用：空→错；`sqlglot.parse(read="sqlite")`；必须**单条**；顶层必须是 Select/Union；黑名单节点 `find_all` |
| `check_sql_safety(sql) -> None` | 仅校验（异常 `SQLUnsafeError`） |
| `check_sql_safety_with_tables(sql) -> set[str]` | **单次解析**同时完成校验 + 表名提取（已剔除 CTE 名） |
| `extract_referenced_tables(sql) -> set[str]` | 单独提取表名 |

### 6.2 `sqlgen/validator.py` — 输出二次校验

| 函数 | 说明 |
|---|---|
| `extract_json(raw) -> str` | 剥离 ```` ```json ```` 围栏，取最外层 `{...}` |
| `parse_llm_output(raw) -> dict` | 解析为 JSON 对象 |
| `validate_output(data, allowed_tables, catalog) -> dict` | 校验并规范化 `sql/tables/columns/explanation`；`tables` 必须真实存在且 ⊆ Schema Linking；`columns` 必须「表.字段」；`sql` 通过 `check_sql_safety_with_tables` 且引用表 ⊆ `allowed_tables`；返回去重后的结果。异常 `SQLGenOutputInvalidError` / `SQLGenSchemaMismatchError` / `SQLTableMismatchError` / `SQLUnsafeError` |

### 6.3 `sqlgen/prompt.py` — Prompt 组装

| 名称 | 说明 |
|---|---|
| `SYSTEM_PROMPT` | 系统角色 |
| `BUSINESS_RULES` | 业务口径（V1.3） |
| `build_prompt(question, link_result, fs_result) -> str` | 主组装函数 |
| `semantic_contract_block()` / `date_window_block()` 等 block 函数 | 条件性注入片段 |
| E4~E7 规则段 | 历史实验规则 |

**条件性注入机制**：仅当 `SQLGEN_EXTRA_RULES` 含对应开关**且**题目被确定性识别时追加规则块；未命中时 Prompt 与冻结基线**逐字节相同**（该性质有测试守卫）。

### 6.4 `sqlgen/semantic_contracts.py` — E9 / E10 / E11

三个确定性检测函数（全局口径 / 比值方向 / 排名破平），返回 Contract dataclass；`to_prompt_block()` 输出约束文案。**默认关闭**。

### 6.5 `sqlgen/entity_constraint.py` — E8
`detect_analysis_entity_constraint(question)`：识别「统计实体约束」并生成约束块。

### 6.6 `sqlgen/date_window.py` — E12
`detect_date_window(question) -> DateWindowContract | None`：用 `_DATE_WINDOW_PATTERNS`（explicit_year/quarter/half_year/month/relative_days/ytd/this_period/annual/yoy）确定性识别「题目已给出时间范围」；未给出返回 `None`（不注入）。`DateWindowContract.to_prompt_block()` 输出「保持时间窗口语义」约束。
> 注意：year 模式**必须带「年」字**（`20\d{2}\s*年`），否则「2000元」价格档会被误判为年份。

### 6.7 `sqlgen/generator.py` — `SQLGenerator`

| 方法 | 说明 |
|---|---|
| `__init__(provider=None, schema_linker=None, fewshot_retriever=None)` | 未注入时复用同一 provider 实例 |
| `generate(question) -> SQLGenerationResult` | **自带** Schema Linking + Few-shot（默认入口） |
| `generate_with_context(question, link_result, fs_result)` | 使用调用方已备好的前两步结果，**不重复调用**（LangGraph 用此入口，避免重复 LLM 调用） |

`FEWSHOT_TOP_K = 3`。内部顺序：拼 Prompt（system+user）→ `provider.generate(temperature=0.0)` → `parse_llm_output` → `validate_output` → 组装 `SQLGenerationResult(question, sql, tables, columns, fewshot_examples, explanation)`。

## 7. `sqlexec/` — 只读执行器

### `sqlexec/executor.py`

| 名称 | 说明 |
|---|---|
| `MAX_RESULT_ROWS = 500` | 结果截断上限（集中配置） |
| `execute(sql) -> SQLExecutionResult` | 三步：① `check_sql_safety`（最后一道防线，不信任上游）② `check_sql_scope`（**打开连接前**拒绝未定义别名）③ 只读连接执行 |

**执行细节**：
- `fetchmany(MAX_RESULT_ROWS + 1)` 判断截断（不把全量结果读进内存，也不二次执行取精确总数）。
- `truncated = len(raw_rows) > MAX_RESULT_ROWS`；`row_count = len(rows)`。
- `execution_time_ms` **只统计** `cursor.execute + fetch`，不含任何 LLM 时间。
- 异常：`SQLExecutionSafetyError`（未执行）/ `SQLExecutionScopeError`（未执行）/ `SQLExecutionDatabaseError`（执行失败）。

`sqlexec/models.py`：`SQLExecutionRequest` / `SQLExecutionResult(columns, rows, row_count, truncated, execution_time_ms)` / `SQLExecutionResponse`。

## 8. `sqlrepair/` — 有限自修复

### `sqlrepair/repairer.py`

| 类 / 方法 | 说明 |
|---|---|
| `SQLRepairer.repair(request) -> SQLRepairResult` | 构造修复 Prompt（含 few-shot **仅作上下文，失败不阻断**）→ LLM → `validate_repair_output`；**只生成修复 SQL，不执行** |
| `SQLExecuteWithRepairOrchestrator.run(question, sql, tables, columns)` | 有限闭环：执行 → 失败 → Repair(一次) → 校验 → 二次执行 |

**Orchestrator 计数语义**：
| 场景 | `execute_count` | `repair_count` |
|---|---|---|
| 首次执行成功 | 1 | 0 |
| Safety 拒绝 | 0 | 0（不触发 Repair） |
| 数据库错误 → Repair → 二次执行成功 | 2 | 1 |
| 数据库错误 → Repair 被拒 / 修复后 Safety 拒绝 | 1 | 1 |

`_REPAIR_FEWSHOT_TOP_K = 2`。

`sqlrepair/models.py`：`SQLRepairRequest` / `SQLRepairResult` / `SQLExecuteWithRepairResult` / `sanitize_execution_error()`（错误信息脱敏）。
`sqlrepair/prompt.py`：`SYSTEM_PROMPT` / `build_repair_prompt(...)` / `format_fewshot(...)`。
`sqlrepair/validator.py`：`validate_repair_output(...)`。
`sqlrepair/errors.py`：`SQLRepairError` / `SQLRepairOutputInvalidError` / `SQLRepairSafetyError` / `SQLRepairSchemaError`。

## 9. `sqlcheck/` — 作用域与 Fan-out 检查

### 9.1 `sqlcheck/scope_validator.py`
`check_sql_scope(sql) -> ScopeCheckResult`：检测**未定义的表别名 / 列限定符**。`ScopeViolation` / `ScopeCheckResult(ok, messages)`。
> 作用：在打开数据库连接前，把「必然失败」的 SQL 以更可操作的错误信息拒绝掉（Task37 / E-0099）。

### 9.2 `sqlcheck/fanout_detector.py` — E3（FROZEN）
`analyze_fanout(sql) -> FanoutDiagnosis`：仅输入 Pred SQL（**不读 Gold**），检测 `orders × order_items` 粒度风险。
> E3 属**机制验证（proof of concept）**，已冻结；不得表述为「Hint 提升 EX 3 个百分点」。已知限制：只检测该单一粒度、子查询剪枝未生效、未限定列名存在盲区。

## 12. `agent/` — LangGraph 编排

### 12.1 `agent/state.py`
`AgentState(TypedDict, total=False)`，字段见 [01-架构总览 §3.3](./01-架构总览.md#33-状态定义agentstatepy)。`trace` 使用 `Annotated[..., operator.add]`。

### 12.2 `agent/models.py`
`AgentRequest`（`question`：1~500 字符）/ `AgentResult` / `AgentResponse`。

### 12.3 `agent/nodes.py`
| 名称 | 说明 |
|---|---|
| `AgentComponents`（dataclass） | 依赖注入容器：`schema_linker` / `fewshot_retriever` / `sql_generator` / `sql_executor` / `sql_repairer`（测试可全替换为 fake） |
| `make_nodes(components) -> dict[str, Callable]` | 构建 8 个节点函数 |
| `_wrap(node, fn)` | 包装器：计耗时、写 TraceEvent（三态）、**捕获异常不 raise**（转终态并写 `http_status`/`error_type`）；失败后节点记 `skipped` |
| `_http_status_for(exc)` | `LLMAuthenticationError → 502`；其他 `LLMError → 503` |
| `_node_input_summary` / `_node_output_summary` | 轻量摘要（**不保存完整 SQL / rows / 隐私数据**） |
| `route_after_sql_safety(state)` | `sql_safety_ok ? "execute" : "result"` |
| `route_after_execute(state)` | 成功/ Safety 拒绝/ `repair_count>=1` → `result`；否则 `repair` |
| `route_after_repair(state)` | `repair_ok ? "repaired_execute" : "result"` |
| `build_agent_result(state) -> dict` | 汇总终态为对外输出（保留全部中间证据 + Trace） |

`FEWSHOT_TOP_K = 3`。`sql_generate_node` 通过 `_restore_objects()` 从 State 重建 `SchemaLinkResult` / `FewShotResult`，再调 `generate_with_context`（避免重复 LLM 调用）。

### 12.4 `agent/graph.py`
| 名称 | 说明 |
|---|---|
| `default_components()` | 生产默认组件（真实模块，provider 取当前默认） |
| `build_agent(components=None)` | 构建并编译 LangGraph（`StateGraph(AgentState)` + 8 节点 + 2 处条件边） |
| `get_default_graph()` | **进程级缓存**：以「构建函数身份」为键，`build_agent` 被 monkeypatch 时缓存自动失效 |
| `clear_default_graph_cache()` | 清缓存 |
| `run_agent(question, components=None) -> AgentResult` | `components=None` 复用缓存图；显式传入按需构建（保证测试注入语义） |
