## 3. 认证状态管理（`src/auth/AuthContext.tsx`）★ 重点

这是前端最需要注意的设计，因为它区分了「未登录」与「后端不可用」。

### 3.1 五态状态机

| `/api/auth/me` 结果 | `AuthStatus` | 行为 |
|---|---|---|
| HTTP 200 | `authenticated` | 落地用户信息 |
| HTTP **401 / 403** | `anonymous` | **清理**本地会话（凭证无效） |
| **网络失败**（连不上） | `backend_unavailable` | **保留**会话 + 显示重试页 |
| **5xx** | `backend_error` | **保留**会话 + 显示重试页 |
| 其它 4xx / 无法归类 | `anonymous` | 清理会话（宁可回登录页也不假装登录） |
| 启动对比中 | `loading` | 显示恢复中 |

> 关键语义：「服务挂了 ≠ 你登出了」。只有 401/403 才清理会话。

### 3.2 对外 API（`useAuth()`）

| 成员 | 说明 |
|---|---|
| `user` / `accessToken` / `expiresAt` | 会话数据 |
| `isAuthenticated` / `isLoading` / `status` | 状态 |
| `login(username, password)` | 登录 → `applySession()` 保存会话 |
| `register(username, email, password)` | 注册成功后**自动登录** |
| `logout()` | 尽力调后端登出，随后**无条件**清理本地会话 |
| `refreshCurrentUser()` | 重新 `GET /api/auth/me` |
| `retryBackendCheck()` | 后端不可用/异常时的重试 |

### 3.3 `ProtectedRoute`
统一路由守卫，按状态分派：`loading` → 恢复中提示；`backend_unavailable` / `backend_error` → `<BackendUnavailable onRetry=...>`；未认证 → `<LoginPage onSuccess=...>`；否则渲染子内容。
> 页面内部**不得再散落** `if (!user)` 判断。

## 4. HTTP 层（`src/api/http.ts`）★ 重点

### 4.1 配置
- `API_BASE_URL`：优先 `import.meta.env.VITE_API_BASE_URL`，默认 `http://127.0.0.1:8000`（去掉尾部 `/`）。
- 会话存储键：`ecom.auth.session`（**仅**存 `accessToken` / `expiresAt` / `user` 摘要；**绝不存 password**；前端**不解析** token 内容）。

### 4.2 错误类型（两类必须分开）

| 类型 | 含义 |
|---|---|
| `HttpApiError(status, message)` | 请求**到达了**服务器但非 2xx（文案取 `detail` 或 `error`） |
| `HttpNetworkError` | 请求**根本没到达**服务器（后端未启动/端口不通/DNS 失败） |

`classifyRequestFailure(err) -> "unauthorized" | "backend_unavailable" | "backend_error" | "other"` 是**唯一分类源**（调用方不得自行 `instanceof TypeError`）。`AbortController` 取消不属于故障，**原样透传**。

### 4.3 `apiRequest<T>(path, options)`
- 默认 `auth=true` → 自动注入 `Authorization: Bearer <token>`（登录/注册传 `auth:false`）。
- 自动 JSON 序列化；`204` 不解析 body。
- **401 统一处理**：清空本地会话并广播事件给监听者（`onUnauthorized`）；`/api/auth/login` 与 `/api/auth/register` 在豁免名单内（避免重定向循环）。

### 4.4 各领域 API 模块
`api/agent.ts`（`analyze()` + `AgentTraceEventDto` 类型）、`api/auth.ts`、`api/history.ts`、`api/insights.ts`、`api/system.ts`。
> 页面**不得**散落 `fetch`，一律经由 `apiRequest`。

## 6. 7 阶段流程可视化（`AnalysisWorkflow.tsx`）

**7 个 UI 阶段**（与后端 8 节点的映射）：

| # | UI 阶段 | 对应后端节点 |
|---|---|---|
| 0 | 问题理解 | （客户端） |
| 1 | Schema 匹配 | `schema_link` |
| 2 | Few-shot | `fewshot_retrieve` |
| 3 | SQL 生成 | `sql_generate` |
| 4 | SQL 校验 | `sql_safety` |
| 5 | SQL 执行 | `sql_execute` / `sql_repair` / `sql_execute_repaired` |
| 6 | 结果生成 | `result` |

> Repair 三节点**统一归入第 5 阶段**作子状态，**不新增第 8 阶段**。

**状态来源**：`loading` 时仅当前阶段 `active`（**不虚构已完成**）；`done` 全部完成；`error` 时定位**第一个 `status==="error"` 的节点**对应阶段标红，其前为 `done`、其后为 `todo`。
**阶段详情**优先展示后端**真实 Trace** 的 `output_summary`（经 `SUMMARY_TEXT` 白名单挑选 key，最多 4 个），`message` 作补充；SQL 生成阶段额外展示 `generatedSql`。**前端不编造流程信息**。

## 7. 图表配置（`src/data/charts.ts`）

- 三个构造函数**只负责视觉**，数据由调用方传入（**不再持有任何 demo 数据**）：
  - `salesTrendOption(points)` — 销售趋势折线图；
  - `categorySalesOption(items)` — 类目销售柱状图（5 色板）；
  - `presentationChartOption(points)` — 汇报模式折线（取最近 7 个月）。
- **单位约定**：接口返回 `sales` 单位是**元**；图表按设计展示为**万元**（1 位小数）。转换 `toWan()` **只发生在这里**，不改动接口原始值。
- 视觉约束（对齐 UI/UX v1.0 §16）：线宽 ≥ 2px、标签清晰、网格线淡、**无 3D、无复杂动画**。
