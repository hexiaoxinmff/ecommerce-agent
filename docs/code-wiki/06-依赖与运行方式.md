## 3. 模块依赖关系

### 3.1 后端分层依赖方向（单向，禁止反向依赖）

```text
┌──────────────────────────────────────────────┐
│ api/routes  (FastAPI 路由)                     │  ← 只依赖 schemas + 领域模块
└───────────────┬──────────────────────────────┘
                ▼
┌──────────────────────────────────────────────┐
│ agent  (LangGraph: graph / nodes / state)     │  ← 编排领域模块
└───────────────┬──────────────────────────────┘
                ▼
┌──────────────────────────────────────────────┐
│ 领域层: schema / fewshot / sqlgen / sqlexec / │
│         sqlrepair / sqlcheck / auth / trace   │
└───────────────┬──────────────────────────────┘
                ▼
┌──────────────────────────────────────────────┐
│ 基础设施: llm / db / core(config)             │  ← 最底层，不反向依赖
└──────────────────────────────────────────────┘
```

关键依赖边（谁调谁）：

```text
agent/nodes.py  ──→ schema.SchemaLinker
                ──→ fewshot.FewShotRetriever
                ──→ sqlgen.SQLGenerator
                ──→ sqlgen.safety.check_sql_safety_with_tables
                ──→ sqlexec.SQLExecutor
                ──→ sqlrepair.SQLRepairer
                ──→ trace.recorder

sqlgen.SQLGenerator      ──→ llm.get_llm_provider()
sqlrepair.SQLRepairer    ──→ llm.get_llm_provider()
schema.SchemaLinker      ──→ schema.metadata.SchemaCatalog
sqlexec.SQLExecutor      ──→ sqlgen.safety（二次校验）+ db.sqlite（只读连接）
auth                     ──→ db.appdb（可写）
```

**唯一 LLM 出口**：所有需要 LLM 的模块都通过 `app.llm.provider.get_llm_provider()` 取 Provider，**没有任何模块直接 new MimoProvider / BailianProvider**。这是 Provider 可插拔的关键。

### 3.2 进程级缓存（避免重复构建）

| 缓存 | 位置 | 键 |
|---|---|---|
| LangGraph 图 | `agent.graph.get_default_graph()` | 以 `build_agent` 身份为键 |
| Schema 目录 | `schema.metadata.SchemaCatalog.get_cached()` | — |
| Few-shot 数据集 | `fewshot.dataset.get_dataset()` | `lru_cache` |

改测试时若需隔离，调用 `clear_default_graph_cache()` / `SchemaCatalog.clear_cache()` / `reload_dataset()`。

### 3.3 评测层依赖

```text
scripts/run_eval.py
   ├─→ evaluation.benchmark_contract（Preflight）
   ├─→ scripts.check_benchmark_leakage（Leakage Gate）
   ├─→ evaluation.runner（eval_single_item / hash gate，内部调 app.agent.graph.run_agent）
   ├─→ evaluation.normalization（EX 比较）
   ├─→ evaluation.metrics（聚合）
   └─→ evaluation.report（落盘）
```

## 4. 环境变量（`.env`）

复制模板：Windows `copy .env.example .env`；macOS/Linux `cp .env.example .env`。

> **硬约束**：真实 API Key **只允许**存在于本机 `.env` 或系统环境变量。`.env` 已被 `.gitignore` 排除。前端环境变量在 **另一个文件** `frontend/.env.example`（Vite 只读 `frontend/` 下的 `.env`）。

### 4.1 LLM Provider（核心）

| 变量 | 默认 / 示例 | 说明 |
|---|---|---|
| `LLM_PROVIDER` | `bailian` | 可选 `bailian`（推荐运行）\| `mimo`（正式评测基线） |
| `LLM_MODEL_LOCK` | `true` | 默认单模型锁定；正式评测契约要求 `true` |
| `DASHSCOPE_API_KEY` | — | 百炼 Key 的**唯一**来源（刻意不提供别名） |
| `BAILIAN_API_BASE` | `https://dashscope.aliyuncs.com/compatible-mode/v1` | OpenAI 兼容端点 |
| `BAILIAN_MODEL` | `qwen3.7-flash` | — |
| `BAILIAN_PRIMARY_MODEL` | `qwen3.7-flash` | 契约声明的固定 model（**唯一权威**） |
| `BAILIAN_TIMEOUT` | `30` | 秒 |
| `BAILIAN_FREE_TIER_ONLY` | `true` | 仅当 `LLM_MODEL_LOCK=false` 时生效 |
| `BAILIAN_FALLBACK_MODELS` | （注释） | 免费额度模型池，正式 benchmark 必须为空 |
| `MIMO_API_KEY` / `MIMO_BASE_URL` / `MIMO_MODEL` / `MIMO_TIMEOUT` | （注释） | 可选：正式评测基线 Provider |
| `LOCAL_LLM_BASE_URL` / `LOCAL_LLM_API_KEY` / `LOCAL_LLM_MODEL` | （注释） | 可选本地模型，默认关闭 |

> 百炼的 `thinking` 已在代码里**物理锁死为 `false`**（字面量），刻意不提供可覆盖的环境变量——因其推理链按 output token 计费。

### 4.2 数据路径与运行

| 变量 | 默认值 | 说明 |
|---|---|---|
| `ECOMMERCE_DB_PATH` | `db/ecommerce.db` | 业务库路径（只读） |
| `APP_DB_PATH` | `db/app.db` | 应用库路径（可写） |
| `FEWSHOT_DATASET_PATH` | `data/fewshot/ecommerce_examples.json` | Few-shot 数据集 |
| `CORS_ORIGINS` | `http://localhost:5173` | 逗号分隔；⚠️ 浏览器把 `localhost` 与 `127.0.0.1` 视为不同 origin |
| `AUTH_SESSION_TTL_SECONDS` | `604800`（7 天） | 会话有效期 |
| `SQLGEN_EXTRA_RULES` | 空 | **实验开关**（E 系列附加规则，仅作用于 `sql_generate` 节点），默认关闭 |

环境变量读取的**唯一入口**是 [core/config.py](file:///f:/基于%20Text2SQL%20的电商智能数据分析%20Agent/backend/app/core/config.py)。

## 6. 数据库初始化

两个库**独立初始化**，顺序无强依赖，但登录与查询都需要它们就位。

```bash
# 业务库（会删除重建，seed=20260914，完全可复现）
python scripts/init_db.py

# 应用库（幂等，只建 auth_user / auth_session / query_history 三表）
python scripts/init_auth_db.py
```

- `init_db.py` 末尾会执行基本验证：各表行数、业务 SQL 实际结果、**金额口径一致性**（`check_amount_semantics()`）；
- `init_auth_db.py` 会校验实际建出的表与 `EXPECTED_TABLES` 一致，不一致直接 `SystemExit`。

## 7. 启动

### 7.1 推荐：一条命令

```bash
python scripts/start_dev.py
```

[`scripts/start_dev.py`](file:///f:/基于%20Text2SQL%20的电商智能数据分析%20Agent/scripts/start_dev.py) 的执行顺序：

```text
预检: Python 版本 → 后端依赖(9 模块 import) → Node/npm → 前端 node_modules
      → .env 存在 → 数据文件(ecommerce.db + app.db) → 端口(IPv4+IPv6 双探测)
启动: backend = uvicorn app.main:app --host 127.0.0.1 --port 8000   (cwd=backend/)
      frontend = npm run dev -- --port 5173 --strictPort            (cwd=frontend/)
健康检查: 轮询 http://127.0.0.1:8000/api/health，前端等端口开始监听
输出: Backend / Frontend / Health / API 文档 地址块
```

它**不创建第二套启动体系**——调用的就是 §7.2 的两条命令，只是加了预检与明确文案。

**退出码**（供自动化断言）：

| 码 | 含义 | 码 | 含义 |
|---|---|---|---|
| 0 | 成功 | 6 | `.env` 缺失 |
| 2 | Python 版本过低 | 7 | 端口被占用 |
| 3 | 后端依赖缺失 | 8 | 数据文件缺失 |
| 4 | Node / npm 缺失 | 9 | 后端启动失败 |
| 5 | 前端依赖缺失 | 10 | 前端启动失败 |

**常用选项**：

```bash
python scripts/start_dev.py --check-only              # 只预检不启动
python scripts/start_dev.py --only backend            # 只起后端
python scripts/start_dev.py --backend-port 8001 --frontend-port 5174
python scripts/start_dev.py --detach                  # 后台启动并写 PID 文件
python scripts/stop_dev.py                            # 停止后台服务
```

> `--strictPort` 的作用：端口被占用时**报错退出**，绝不静默换到 5174（否则用户访问 5173 会看到别人的服务）。Windows 也可双击 `scripts\start_dev.bat`。

### 7.2 手动：两条等价命令

```bash
# 终端 1 — 后端
cd backend
uvicorn app.main:app --reload            # http://127.0.0.1:8000
                                         # /docs 交互文档；/api/health 健康检查

# 终端 2 — 前端
cd frontend
npm run dev                              # http://localhost:5173
```

前端通过 `VITE_API_BASE_URL` 连接后端（默认 `http://127.0.0.1:8000`，见 `frontend/.env.example`）。生产构建 `npm run build`，检查 `npm run lint`。

### 7.3 验证链路

```bash
curl http://127.0.0.1:8000/api/health
curl http://127.0.0.1:8000/api/system/database
curl -X POST http://127.0.0.1:8000/api/llm/test \
  -H "Content-Type: application/json" -d '{"prompt": "你好"}'
```

> 若未配置 Key，服务仍可启动，但所有依赖 LLM 的接口（`/api/llm/test`、`/api/schema/link`、`/api/sql/generate`、`/api/sql/repair`、`/api/agent/analyze`）返回明确的「未配置」错误。

## 11. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `start_dev.py` 退出码 8 | 数据文件缺失 | 跑 `init_db.py` + `init_auth_db.py` |
| 退出码 7 | 端口被占用 | 停占用进程或 `--backend-port/--frontend-port` 换端口 |
| 退出码 6 | 无 `.env` | `copy .env.example .env` |
| 前端 5173 打不开但无报错 | 手动启动时 Vite 静默换到 5174 | 用 `start_dev.py`（`--strictPort`），或查看终端实际端口 |
| LLM 接口返回「未配置」 | 缺 API Key | 填 `DASHSCOPE_API_KEY` 并重启后端 |
| `run_eval.py` 退出码 5 | 未满足 Preflight 契约 | 检查 §4.1 的 4 个关键变量 |
| `run_eval.py` 退出码 2 | Gold 漂移 | 确认未改动 DB 生成逻辑；必要时按版本规则升级 `database_version` |
