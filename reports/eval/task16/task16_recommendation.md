| 题目 | 真实原因 | 归属 |

## Q2：哪些问题是 Prompt 能解决的？

**几乎没有全新空间**。证据链：
- Task 14.2 已用 E4（Output Contract）/E5（Metric Semantics）/E6（Nested Aggregation）/E7（CASE Boundary）做四组独立实验，**目标题均未修复、总体无增益**（E4-E7 结果见 legacy 文档）；
- E-0082/0083 在 V1.3 中已有 JSON 输出结构约束，但缺的是"占比题要输出维度列"这类**列级输出契约** —— E4 就是干这个的，已证无效；
- E-0086/E-0095 的 V1.3 已含"两阶段聚合/防 fan-out/占比同窗口"文字规则，但模型生成侧仍犯（规则文本 ≠ 结构遵从）；
- 因此**本任务没有提出任何新的 Prompt 规则**。结论：Prompt 文本规则对这类"结构级"错误收益极低，不再投入。

## Q3：哪些问题 Few-shot 更合适？

Few-shot（示范型）适合**把"结构/列形状"具象化**的问题：
- **S1 输出列契约**（E-0082/0083）→ cand_A1（label+value 多列示范）；
- **S2 总数列/结构统计**（E-0090 列部分）→ cand_A2（分项+总数列示范）；
- **S3 聚合粒度/防 fan-out**（E-0086）→ cand_C1（订单粒度先聚合再 JOIN 明细）；
- **S4 第二层平均基准**（E-0095）→ cand_C2（阈值前置过滤后再平均）。

即：**E9（A1+A2）与 E11（C1+C2）是 Few-shot 的适配方向**。

## Q4：哪些问题应该交给生成后 Validator？

- **列引用/别名合法性**（E-0099 类：`r.region` 未定义）→ **静态可拦截**（sqlglot 作用域别名校验，零误报子集），是 E8 最扎实的部分；
- **输出形状契约**（E-0082/83/90 的缺列）→ 理论上 validator 可拦截，但**必须搭配"题目侧期望形状契约"**（sidecar 元数据），否则纯静态无法知道自己该期望几列 → 属于"契约驱动校验"，可作为 E8 的第二能力；
- **过滤条件遗漏**（E-0095/E-0090 的 WHERE/HAVING 缺失）→ **不适合**（本质是 NL→SQL 条件映射，非静态范畴）。

## Q5：E-0099 是否值得单独改 Repair？

**三选一结论：`continue_observe`（继续观察）**。
- 直接证据：只有 1 例（1/100）；
- 失败机制：生成层别名不一致（SELECT 用 r、FROM 用 rs）+ Repair 生成的 SQL 仍引用不存在的字段 → 生成 bug 且 Repair 校验滞后；
- 不建议现在改 Repair 主流程（单例收益低、改动风险高）；
- 建议：作为 **E8 P1 静态列引用校验的附带验证点** —— 若 E8 上线后该 pattern 不再出现，即闭环；若后续 ≥2 例重现，再升级为 Repair 专项。

## Q6：下一轮最值得做哪一个独立实验？

**优先：Candidate E9（只增加输出结构 Few-shot：cand_A1 + cand_A2）**。
理由（不是直觉，是证据排序）：
1. 目标集合 S1+S2 覆盖 3 题（E-0082/83/90），其中 E-0082/83 是"数值全对、只差一列" —— **修复成本最低、信号最强**（Pred 的金额、过滤、分子分母全对）；
2. 候选 A1/A2 与目标题检索命中预期最高（表/字段/关键词重合度高），**执行可达性最强**；
3. 风险最小：仅增加 2 条 few-shot（不动 retriever/校验/Repair），意外回归面最小；
4. 结果可判读：只要看"E-0082/83 是否补上 label 列"即可快速验证假设。

**次选：Candidate E11（cand_C1 + cand_C2）** —— S3/S4 也适合 few-shot，但目标题检索命中预期中低（维度不同），且 E-0086 是 extra_hard 结构题，修复难度高于 E-0082/83 → 排在 E9 之后。

**E8 与 E10**：E8 保留为候选（P1 别名校验零误报、P2 需 sidecar 契约），E10 本轮不做（目标为空）。

## Q8：成功/失败的判断标准是什么？

以 E9 为例（E11/E8 同构替换目标题）：

**成功（全部满足才算"有效"）**：
1. Leakage Gate PASS（候选已验）；
2. Overall EX ≥ 90.0%（不下降）；
3. E-0082 / E-0083 / E-0090 至少 **1 题**修复；
4. 非目标 Bad Case（其余 7 题 + 原本 PASS 的 90 题）无新增缺失（回归 ≤ 1 题且可解释）；
5. Conditional EX 不下降；
6. Provider failure / Timeout 不新增；
7. 至少 2 次运行结果趋势一致（Mimo 随机性内），不能单次定论。

**失败判定**：目标 3 题全未修复；或 Overall EX 下降 ≥ 1pt；或新增非目标失败 ≥ 2 题。此时**停止该方向，不做局部修补**，保留结果归档后回到总顾问决策。

> 严禁用"只比较目标 Bad Case 的修复"作为唯一判据；必须同时观测全量回归指标。
